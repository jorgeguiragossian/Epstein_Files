# Prepared timeframe briefs with citations

The first timeframe view is `/timeframes` locally and `timeframes.html` on GitHub Pages. It selects prepared, AI-assisted editorial drafts by inclusive reviewed primary document dates, dataset and optional curated name. It does not call an AI API at runtime, generate a new cross-document narrative, or send source text to another service. GitHub Pages remains static and contains no credentials.

Eight initial briefs summarize limited content on explicitly cited PDF pages. They were prepared by Codex from native page text and source context; they are not human-verified findings or full-document summaries. Each point has a source-attributed statement, a separate limitation, and an exact extracted quotation with a page citation. Statements about proposed calls, intended referrals, flight discussions, filing schedules and report claims do not establish that an event occurred or an allegation is true. Redacted identities and credentials are not reconstructed.

All 36 reviewed dated pilot documents can participate in timeframe selection. Eight have prepared content briefs; the other 28 have only reviewed date evidence. The latter are hidden by default and can be included explicitly. The remaining 64 PDFs lack usable reviewed primary dates and are excluded. A zero-brief selection can still contain date-evidence-only documents; the view explains the distinction.

Name filtering is document-level: at least one page must match the curated literal name, and a brief may cite another page. This differs from the word cloud's page-only name filter and is stated in the interface. Dates refer to the containing document's reviewed primary day, not each event, attachment or quoted email inside it. Every card links separately to date evidence and its rationale. Cards sort newest document date first; settings persist in the URL.

The tracked [brief file](../data/pilot/2026-11-01/timeframe-briefs.json) stores the source PDF hash, cited page-text hash, exact quote, limited scope, draft status and point limitations. `scripts/prepare-timeframe-briefs.py` reproduces these curated drafts; it is not an automatic summarizer. Local API and static export validate all citations against the original page text. Stale source/page hashes, absent quotations and missing citations reject the build/API request. Existence checks cannot establish semantic accuracy of a paraphrase or authenticate the source.

`viewer/timeframes.py` validates evidence and selects records. The public build exports validated selection metadata and prepared briefs. Synthetic tests cover changed citations, unsupported status, inclusive dates, document-level name selection, missing briefs and invalid filters. Static API comparisons check default, ranged, dataset, person, empty and uncertain-reminder cases. Existing source text, email parsing, reviewed dates and other annotations remain unchanged.

Live on-demand AI summarization would require a separate server-side service, model choice, usage controls and evaluation. This milestone is the reviewable static starting point, with its limited prepared coverage visible rather than silently filling gaps.
